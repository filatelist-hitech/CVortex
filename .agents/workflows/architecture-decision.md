# Architecture Decision Workflow

## Trigger

Use this workflow for material decisions affecting architecture, security, persistence, integration boundaries, provider abstraction or long-term maintainability.

## Process

1. Describe context.
2. Identify constraints.
3. List reasonable options.
4. Compare benefits, costs and risks.
5. Check existing ADRs.
6. Research current facts when required.
7. Select the simplest justified option.
8. Record consequences.
9. Create or update an ADR.
10. Validate consistency with existing architecture.
11. Update documentation and state.

## Existing ADR Conflict

Never silently change an accepted ADR.

If evidence invalidates an accepted decision:

- record the conflict;
- propose superseding or amending the ADR;
- retain historical traceability.
