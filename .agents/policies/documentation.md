# Documentation Policy

## Purpose

Keep project knowledge durable, Git-readable and usable through Obsidian.

## Mandatory Rules

- Documentation is Markdown.
- Documentation must remain useful without Obsidian.
- Important documents use frontmatter.
- Material architecture decisions use ADRs.
- Prefer Mermaid for engineering diagrams when reasonable.
- Update documentation with behavior and architecture changes.
- Keep documentation concise and linked.

## Prohibited Behavior

- Undocumented architecture decisions.
- Treating chat history as canonical documentation.
- Storing critical knowledge only in proprietary formats.
- Creating diagrams that are the only source of architectural truth when a text representation is practical.
- Silently contradicting accepted documentation.

## Completion Checks

- Documentation matches current behavior.
- Relevant links are updated.
- Architectural decisions have ADR coverage.
- Markdown renders reasonably in Git viewers.
- Obsidian-specific conveniences do not make documents unreadable elsewhere.
