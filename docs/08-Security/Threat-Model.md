# Phase 06 Security Threat Model

External vacancies, recruiter messages, uploads, HTML/web/API responses and tool output are **untrusted data, never instruction**. The matrix records each threat's own asset and threat source; global categories are not substitutes for the per-threat boundary.

| Threat | Asset | Threat actor / source | Attack surface and scenario | Impact | Preventive controls | Detective controls | Residual risk | Validation / testing strategy |
|---|---|---|---|---|---|---|---|---|
| Prompt injection | trusted instructions, authorized context, truth of candidate content | malicious vacancy, recruiter message, website, upload or tool output | Injected text attempts to override workflow, invoke tools or exfiltrate context | false facts, disclosure, unsafe action | separate trusted prompt/data; minimal owner-scoped context; policy-gated tools; schema and Truth Guard; M1.4 labels vacancy and Career context as untrusted data and exposes no submission tool | safe LLM-run audit; policy/validation failure telemetry | semantic evasion | adversarial vacancy/message/upload fixtures; assert no tool/action/context escape |
| SSRF | internal services, metadata endpoints, network availability | malicious URL/source | Future fetcher follows URL, redirect or DNS rebinding to private address | private-data disclosure, pivot, outage | allowlisted protocols/sources; DNS/IP private/link-local validation; redirect revalidation; time/size limits; isolated egress | request/egress logs; blocked-target alerts | DNS races and parser defects | redirect, encoding, DNS-rebind and blocked-range tests |
| XSS | browser session, rendered candidate/external content | malicious HTML/rich text or generated text | Imported or generated markup executes in a browser | session/data theft, unauthorized actions | render as text; escape by default; sanitize at boundary; CSP | sanitizer decision/error logs; CSP reports | sanitizer bypass | malicious-markup regression fixtures and browser rendering tests |
| File traversal | private storage, converter host, generated files | malicious filename, archive entry or generated path | Path escapes storage root or reaches unintended parser file | file disclosure/overwrite, host compromise | opaque generated names; normalized storage references outside webroot; ownership checks; isolated converter | rejected-path/security logs; converter alerts | parser zero-days | traversal, symlink, archive-path and malformed-file tests |
| IDOR | an individual private resource | authenticated malicious user | Guessed identifier or nested route accesses another resource | unauthorized read/write/delete | server-side resource authorization; non-enumerating denial; explicit audited admin operation | authorization-denial and anomaly audit | missed new endpoint/query | negative read/write/delete/nested-route tests |
| Cross-user access | tenant-scoped aggregates, queues, cache, files and AI context | authenticated user, buggy worker or cache consumer | Owner scope is omitted or forged across relation/job/cache/context | bulk PII and career-content leakage | authenticated server-derived owner; same-owner relation checks; scoped queue/cache/file/context keys | cross-tenant access alerts; correlation audit; anomaly review | missed propagation path | User A vs User B matrix for list, relation, job, file, cache and context selection |
| Malicious uploads | parser/converter availability and stored files | hostile uploaded PDF/DOCX/archive | Spoofed MIME, macro, bomb or malformed parser input consumes or exploits worker | code execution, outage, unsafe file | inspect bytes; quarantine; reject/limit macros, archives and size; resource/time limits; sandbox parser | quarantine/parser failure metrics and alerts | parser vulnerabilities | bomb, spoofed MIME, macro and corrupt-file fixtures |
| Secret leakage | provider keys, BYOK credentials, system secrets | developer/operator mistake, log/export consumer, malicious input | Secret appears in logs, prompt, export, audit or document | account takeover, spend and data exposure | encrypted storage; redaction; masked display; no post-store client return; least privilege | secret-scanning/redaction alerts; credential lifecycle audit | operational error | log/prompt/export/audit redaction tests |
| PII leakage | career/application data, backup/export and provider context | over-broad workflow, provider, backup or unauthorized operator | Excessive context transfer, insecure export or restore exposes private data | privacy breach and loss of trust | context minimization; owner scope; retention/deletion/export policy; encrypted access-controlled backups; provider review | context-size/access logs; restore/export audit | provider or backup compromise | context minimization and restore/export access tests |
| LLM credentials | system and BYOK credential material, provider budget | attacker with stolen key or cross-user credential path | Credential resolution, rotation or provider request uses wrong owner/key | provider misuse, spend and user data exposure | encrypted-at-rest owner-scoped resolution; no prompt/log/client round trip; rotate/delete; least privilege | usage anomaly monitoring; resolution failures; add/rotate/delete audit | valid-key abuse | tenant resolution, rotation, revocation and no-secret-in-run tests |

Security validation is required before each future ingestion, fetcher, parser, credential or context implementation; human approval does not mitigate a failed technical control.

## MCP Gateway extension (2026-09-25)

The disabled-by-default [MCP Gateway](../02-Architecture/MCP-Gateway.md) adds an external tool-call boundary. Authenticated Passport bearer scope, ACTIVE status, owner-scoped queries/RLS, strict tool allowlist/schema, bounded context, per-user rate limits and safe metadata-only logging address token misuse, IDOR, prompt/tool injection, excessive disclosure and log leakage. No MCP tool can approve, send, confirm a Career Fact, fetch arbitrary URLs, read files or invoke SQL/shell. Duplicate/replayed draft submissions are rejected for an existing variant. The OAuth consent page uses Laravel CSRF protection and Passport authorization state/PKCE; MCP POSTs use bearer auth, not browser cookies.

Residual risk: account/tunnel reachability and Passport `resource` audience binding against ChatGPT's current OAuth contract remain unverified. The current semantic Truth Guard depends on `LlmProvider` availability; it fails closed when unavailable. Public HTTPS or Secure MCP Tunnel requires a separate OAuth/security validation before enablement. Test coverage includes owner/foreign read and write, invalid/revoked bearer, missing scope, blocked draft and absence of approval; local Inspector proves only protocol transport, not ChatGPT E2E.
