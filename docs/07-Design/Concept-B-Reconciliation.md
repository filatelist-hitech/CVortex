# Концепция B — Согласование дизайна

## Решение и границы задачи

**Выбрана концепция B (Application Workspace) и завершено согласование дизайна.** Владелец продукта утвердил ментальную модель в техническом задании: это продуктовое решение, а не механический выбор на основе баллов из исследовательских отчётов. Детали верстки прототипа служат входными данными для ревью. Каноническая целевая структура разделов (IA): **Сегодня / Возможности / Карьера / Работодатели / Настройки** (Today / Opportunities / Career / Employers / Settings).

Режим выполнения: `ARCHITECTURE`, репозиторный регламент, один агент, без субагентов. Работа выполнялась по прямому подтверждению владельца с переопределением указателя Preview. Использована ветка `docs/ux-redesign-concepts` на коммите `a62ff0899ea9a2dd2266eb5a972d618f803c9952`, совпадающем с локальным `stage`/`origin/stage`. Ранее сохранённые исследования и записи в файлах состояния не затрагивались. Изменения в боевой код, значения дизайн-токенов, правки базы данных и публикации не производились.

## Анализ источников и границы проверок

В аудит вошли: индексные документы продукта и дизайна, Основы дизайна (Design Foundation), историческая передача из Figma, UX Центра ошибок, материалы Фазы 06 (дизайн продукта, системы, данных и ИИ), Принципы, Границы, Словарь, План развития, базовая архитектура, рамки принятых решений ADR-0004/0007/0009/0012/0013/0014/0016/0017/0022/0023, действующие токены Git и соглашения фронтенда. Файлы `apps/frontend/AGENTS.md`, `package.json`, `page.tsx`, `access-shell.tsx`, `career-workspace.tsx`, `vacancy-workspace.tsx`, `globals.css` использовались для сопоставления текущей реализации без внесения правок в код.

Инструмент `agent-browser` был недоступен. Политика безопасности запрещает протокол `file://`; разрешённый локальный просмотр выполнялся через работающий loopback-сервер внутри каталога исследований. Открывать файлы наружу в публичный интернет запрещено.

В каталоге `brand` и фронтенде отдельного векторного файла логотипа не найдено. Сохраняем текстовое начертание CVortex и существующий градиентный знак; выдумывать новый логотип или заменять его внешними ассетами запрещено. Любой предложенный владельцем логотип должен пройти проверку перед добавлением.

## Реестр согласования дизайн-токенов

| Категория | Токены и наблюдения | Решение и необходимое действие |
| --- | --- | --- |
| **Совместимы** | Все существующие группы `color.*`, `surface.*`, `text.*`, `border.*`, `accent.*`, `state.*`; шрифты, размеры, насыщенность, высота строк, трекинг; отступы, радиусы, тени, анимации, брейкпоинты и слои z-index | Сохранить значения и алиасы. Ни один токен не признан устаревшим из-за новой ментальной модели. Текущий прод использует вручную выписанное подмножество; автоматическая синхронизация пока не настраивалась. |
| **Требуют расширения** | Запланированные алиасы для ролей рабочей области: `workspace.list.selectedSurface`, `workspace.list.selectedText`, `workspace.inspector.surface`, `workspace.review.proposedSurface`, `workspace.status.stale`, `workspace.status.unknown` | В рамках первой задачи обосновать каждую роль и добавить алиасы к существующим `surface.interactive`, `text.primary`, `surface.elevated`, `state.warning`. Эти пути являются предложениями спецификации, а не готовыми токенами. Состояниям неизвестности и устаревания нужен понятный текст, а не только цвет. Новые базовые цвета не требуются. |
| **Устарели** | Явно устаревших не выявлено | Не удалять токены только потому, что прототип их не задействовал. Инструкции по синхронизации с Figma устарели процедурно, но сами значения токенов валидны. |
| **Только для прототипа** | Радиусы 6 и 10 пикселей, кастомные фоны плашек статусов, цвет наведения `#75e6f1`, фиксированная ширина панелей, заголовки 18px, хардкод z-index и letter-spacing, демо-плашки | При подготовке эталона нормализовать в канонические семантические алиасы и шкалы типографики/радиусов. Запрещено копировать эти временные значения в канонический JSON или тему приложения. |

Выделение элементов интерфейса может использовать существующие семантические токены. Алиасы компонентов допустимы только при явной необходимости для чистоты кода; создавать параллельную «вторую тему оформления» запрещено. Проверка лицензий и шрифтов для продакшна остаётся обязательным этапом; шрифты из исследовательской папки не считаются автоматически купленными для коммерческого продакшна.

## Валидация и оставшиеся ограничения

Фактические результаты проверки: предварительная проверка репозитория перед архитектурной записью; рендеринг и взаимодействие во встроенном браузере со скриншотами; аудит источников, решений и индексов; проверка структуры заголовков, метаданных frontmatter, локальных ссылок, таблиц и ссылок на ADR; сверка эталона канонических токенов; сравнение контрольных сумм защищённых файлов; `git diff --check`. Итог проверки документации: **27 файлов Markdown, 20 корректных блоков фронтматтера YAML, 271 ссылка, 44 таблицы, ноль битых ссылок и ошибок**. Аудит токенов: **113 конечных значений, 28 разрешённых алиасов, 378 контрольных сумм файлов без изменений**.

Запуск тестов и линтеров фронтенда не требовался, так как файлы боевого кода не модифицировались. Предыдущие результаты 127 проверок остаются историческим свидетельством прошлых запусков. Полномасштабное визуальное регрессионное тестирование продакшна, попиксельная приёмка экранов человеком, реальное тестирование масштабирования, скринридеров и приёмка живыми пользователями в рамках этого этапа не заявляются. Существующие блокеры по квотам, Preview и окружению сборки остаются открытыми.
