# Спецификация UX Центра ошибок

Главная задача администратора при разборе сбоев — быстро понять, какая операция упала, почему это произошло, на что повлияло, можно ли её повторить и какое действие предпринять дальше, не погружаясь в сырые стектрейсы. Структура экрана следует логике: **Проблема → Причина → Последствия → Действие → Корреляция → Технические детали**. Ранее созданная в Figma черновая страница `04 Error Center · draft` не являлась утверждённым человеком эталоном. В соответствии с решением [ADR-0024](../03-ADR/ADR-0024-git-design-reference-workflow.md), визуальные требования фиксируются в спецификации и исполняемых эталонах компонентов в Git, а дизайн-токены в Git служат машинным источником правды. Использование Figma опционально.

## Аудит полей данных

| Поле в интерфейсе | Источник данных | Доступность | Требуется ли доработка бэкенда |
| --- | --- | --- | --- |
| Причина | Стабильный `error_code`, безопасное сообщение `message`, справочник `ErrorCatalog` | Да, детерминированное сопоставление для известных кодов | Нет |
| Возможность повтора | Поле `retryable` инцидента из `ErrorCatalog` | Да | Нет |
| Рекомендуемое действие | Поле `recovery_action` инцидента | Да | Нет |
| Затронутая операция | Поле `operation` последней ошибки; в списке используется проекция `latest_operation` | Да, если зафиксировано | Нет, небольшая проекция для списка; не угадывать при отсутствии |
| Провайдер и попытка | Поля `provider`, `attempt` последней ошибки; в списке — `latest_provider` | Да, если зафиксировано | Нет, небольшая проекция для списка |
| Последствия сбоя | Поле `impact` инцидента | Да, общее описание на уровне категории ошибки | Нет; никогда не делать домыслов о целостности данных |
| Изменились ли данные | Нет подтверждений коммита записей в подсистеме диагностики | Нет | Нет; честно указывать, что диагностика не может подтвердить изменение данных |
| Категория ошибки | Стабильный код `error_code` | Достаточно подробная | Нет |
| Длительность и HTTP-статус провайдера | Отсутствуют в ответе инцидента/события | Нет | Нет; опускать в интерфейсе |
| Задержка повтора (Retry-After) | Зафиксированная задержка ответа провайдера | Да, если известна | Ограниченное целое число от 0 до 86400 секунд в объекте события; иначе показывать «неизвестно» |
| Корреляция | Идентификаторы запроса, фоновой задачи, LLM, отклика и браузерный `error_ref` | Да, до 20 последних событий | Нет; показывать и давать скопировать сохранённый браузерный идентификатор |
| Частота | Количество событий, время первого и последнего появления | Да | Нет |
| Глобальные метрики | Только постраничный список | Нет надёжных глобальных сумм | Нет; показывать контекст страницы, а не придуманные общие числа |
| Связанные инциденты | Точный поиск по корреляционным ID | Доступно через ручной поиск | Нет; без построения сложных графов и додумывания связей |

## Направление дизайна

- **Цвета:** `surface.canvas #070B18`, `surface.default #0B1224`, `surface.elevated #111C35`, `text.primary #F7F9FC`, `accent.primary #35D6E8`, семантические токены предупреждений и ошибок из `brand/tokens/cvortex.tokens.json`. Это существующие токены дизайн-системы, а не новые цвета.
- **Типографика:** шрифт Space Grotesk. Заголовок страницы — 32px / жирность 600, заголовок инцидента — 24px / 600, основной текст — 16px / 400, метаданные — 14px / 400, кодовые блоки — 12–14px / 400. Имена классов исключений в основных текстах не выводятся.
- **Компоновка:** выравнивание по левому краю, ограниченная ширина строки для комфортного чтения. В списке: заметный поиск, одна компактная строка фильтров, активные чипсы, сдержанная строка сводки и удобные для беглого просмотра строки. На детальной странице: крупный блок принятия решений (причина / последствия / действие / возможность повтора); статус и частота расположены рядом с заголовком. Идентификаторы корреляции и события выводятся табличными строками, а технические детали свернуты под спойлер.
- **Адаптивность:** одна колонка на экранах уже 768px; на экранах 390px фильтры открываются во всплывающей панели со скроллом, разделённой на «Быстрые» и «Расширенные», с закреплёнными кнопками «Применить / Сбросить». Метаданные выстраиваются вертикально, длинные ID визуально обрезаются, но копируются целиком. В строках событий выводятся число, месяц и локальное время; полный год, секунды и часовой пояс остаются в доступной подписи для скринридеров. На десктопе блок решений задаёт сильный визуальный акцент; на мобильных сохраняется тот же порядок чтения.
- **Доступность:** интерактивные элементы от 44px, сочетание цвета и текстовой подписи для важности и статуса, нативные кнопки и спойлеры `<details>`, видимый контур фокуса, подписанные поля поиска и кнопки копирования, оповещения скринридера об изменении данных, поддержка отключения анимаций (reduced motion), отображение часового пояса у меток времени. При загрузке детальной страницы озвучивается имя выбранного инцидента; фокус переводится на заголовок только если пользователь не успел переключиться на другой элемент. При возврате назад по клавиатуре фокус восстанавливается на строке исходного инцидента в списке.

```text
Десктоп:     Поиск ────────────────── Обновить
             Быстрые фильтры · Дополнительные фильтры
             [Открыт] [Критический] [Количество результатов]
             Строки инцидентов: название / причина / статус / частота

Детальный:   Назад · действия со статусом
             Название / код / частота
             ┌ Причина → Последствия → Действие → Возможность повтора ┐
             Контекст · Корреляция
             Недавние события (свернутые строки)
             Технические детали (свернуто)

Мобильный:   Поиск
             Панель фильтров · чипсы
             Карточки списка / детальный экран в одну колонку
             Технические детали в самом конце
```

Главный визуальный акцент детальной страницы — панель принятия решений. Равнозначные карточки похоронили бы призыв к действию. Для контекста и строк событий сознательно выбраны сдержанные разделители. Ревью дизайна человеком опирается на [Design Handoff](Design-Handoff.md); зависимость от согласования макетов в Figma снята.

## Визуальные подтверждения

Работоспособность проверена на экранах шириной 1440px (десктоп), 820px (планшет) и 390px (смартфон) на синтетических инцидентах. Блок решений остаётся в пределах первого экрана на каждом разрешении; технические подробности свернуты, горизонтальное переполнение отсутствует. Скриншоты зафиксированы на синтетических фикстурах (бинарные снимки экрана были удалены в PR #51 в целях оптимизации репозитория):

- Список на десктопе (`error-center-desktop-list.png`)
- Детальный экран на десктопе (`error-center-desktop-detail.png`)
- Детальный экран на смартфоне (`error-center-mobile-detail.png`)

Черновик в Figma создавался до реализации. Лимиты бесплатного тарифа Figma помешали актуализации снимков, поэтому канонической фиксацией служат спецификация и браузерные снимки экрана эталона.

Подтверждения в браузере получены на синтетических данных и продакшн-сборке фронтенда. Проверены список, панель фильтров и детальный экран на всех требуемых ширинах; проверка охватила повтор операции, смену статуса, клавиатурную навигацию, пустое состояние при поиске и отсутствие горизонтальной полосы прокрутки:

## Согласование с рабочей областью отклика

Сохраняются: диагностика с приоритетом решений, доступ к `/diagnostics` только для администратора, детерминированные причины, безопасная корреляция, повтор точной упавшей операции и регламент задержек. Диагностика — это служебная утилита в Настройках, а не инспектор подтверждений пользователя. Ошибки пользовательских операций отображаются по месту внутри рабочей области по цепочке «Проблема → Причина → Последствия → Действие» с безопасным кодом ошибки без сырых трейсов.

## Правила безопасного вывода контента

Названия и причины формируются строго по фиксированной таблице соответствия кодов и безопасных строк API. Для неизвестных кодов выводятся общее название ошибки и явная отметка «причина неизвестна»; запрещено выдавать имя класса исключения или стектрейс за понятный диагноз. Описание последствий остаётся на уровне категории. Интерфейс никогда не утверждает, что данные точно остались без изменений. Полные ID копируются по клику, но по умолчанию отображаются в сокращённом виде. В краткую сводку попадают только код, ID инцидента, последний ID запроса, операция и время. Никаких промптов, резюме, сырых ответов провайдеров, паролей, секретов или абсолютных путей в интерфейс или буфер обмена не попадает.

Фильтр провайдеров сопоставляет провайдера последней зафиксированной ошибки. Поиск и фильтры работают совместно; при отсутствии совпадений интерфейс сообщает, какие фильтры сработали, и предлагает сбросить фильтры с сохранением строки поиска. При сбое запроса статусная кнопка повторяет только свой идемпотентный PATCH-запрос, блокируясь на время отправки.

Синхронные операции с черновиками отклика учитывают числовой заголовок `Retry-After` от 0 до 86400 секунд при повторяемых ошибках API. Ненулевая задержка выводится в понятном сообщении восстановления и блокирует действия генерации, редактирования и согласования до истечения таймера; действие отклонения остаётся доступным всегда, так как не отправляет запросов во внешние API. Браузер сохраняет только детерминированную временную метку окончания блокировки, синхронизирует её между открытыми вкладками и восстанавливает таймер при перезагрузке страницы. При отсутствии или некорректности заголовка искусственные паузы не выдумываются.
