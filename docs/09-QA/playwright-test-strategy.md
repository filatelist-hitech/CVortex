# CVortex Playwright Test Strategy

## 1. Purpose & Risk-Based Approach

Стратегия тестирования UI CVortex фокусируется на критических бизнес-инвариантах и рисках нарушения целостности данных пользователя.

### Ключевые принципы:
1. **Truth-first**: неподтверждённые карьерные факты никогда не должны автоматически становиться подтверждёнными или попадать в одобренные материалы.
2. **Multi-user isolation**: пользователь ни при каких обстоятельствах не должен иметь доступ к данным другого пользователя (факты, вакансии, отклики).
3. **Deterministic before AI**: тесты не зависят от случайного вывода внешних LLM; используются детерминированные мок-провайдеры и синтетические сценарии.
4. **Human Approval**: разделение принятия предложения (Accept) и окончательного одобрения текста (Approve).

## 2. Test Pyramid & Boundaries

- **Unit/Component (Vitest)**: изолированная логика рендеринга и React-компонентов.
- **Backend API (PHPUnit/Pest)**: SQLite/PostgreSQL тесты роутов, политик и RLS.
- **Playwright UI / E2E**: сквозные проверки через браузер:
  - взаимодействие пользователя с формами и диалогами;
  - корректность навигации и отображение состояний (empty, loading, error, success);
  - поведение при сетевых ошибках и сбоях провайдеров анализа;
  - соответствие WCAG 2.1 AA доступности;
  - адаптивное отображение на мобильных и планшетных экранах.

## 3. Test Data Management

- Используются строго вымышленные (синтетические) данные:
  - email с префиксами `qa-synthetic-*.test`;
  - синтетические факты и описания вакансий;
  - 64-символьные одноразовые токены приглашений.
- Каждый тестовый сьют оперирует независимыми сущностями, исключая зависимость от порядка выполнения тестов.
